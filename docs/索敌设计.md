# 自走棋自动战斗：寻敌与索敌系统设计文档

## 1. 文档目标

本文档用于指导 Codex 在当前 Godot 自走棋自动战斗 demo 中实现基础索敌功能。

当前阶段只实现两种索敌模式：

1. `NEAREST`：最近目标模式
2. `LOWEST_HP`：血量最少目标模式

本系统需要能够稳定处理以下情况：

- 当前目标死亡
- 当前目标被移除或节点失效
- 当前目标变为不可选中
- 当前目标离开攻击范围
- 当前目标离开索敌范围
- 当前目标暂时无法到达
- 没有可攻击目标
- 目标切换过于频繁导致单位抖动

---

## 2. 设计原则

### 2.1 解耦原则

索敌系统只负责选择目标，不直接处理伤害和移动。

推荐拆分为三部分：

```text
索敌系统 Targeting
    负责选择 current_target

移动系统 Movement
    负责靠近 current_target

攻击系统 Attack
    负责判断攻击范围、攻击冷却、造成伤害
```

### 2.2 当前阶段不做复杂策略

当前只实现：

```text
NEAREST
LOWEST_HP
```

暂不实现：

```text
随机目标
攻击力最高
后排优先
嘲讽
隐身
仇恨系统
技能独立索敌
```

但代码结构需要方便后续扩展这些模式。

---

## 3. 核心数据结构

每个战斗单位建议至少拥有以下字段。

字段名称可根据项目现有命名调整。

```text
team                阵营，用于判断敌我
hp                  当前生命值
max_hp              最大生命值
is_alive            是否存活
is_targetable       是否可以被选中
current_target      当前攻击目标
target_mode         当前索敌模式
state               当前单位状态
attack_range        攻击范围
search_range        索敌范围
leash_range         追击范围，可选
retarget_interval   重新索敌间隔
retarget_timer      重新索敌计时器
attack_cooldown     攻击冷却
```



推荐后续增加：

```text
unit_id             单位唯一 ID，用于排序稳定
is_stunned          是否被眩晕
is_disabled         是否无法行动
```

## 4. 枚举设计

### 4.1 索敌模式枚举

```text
enum TargetMode {
    NEAREST,
    LOWEST_HP
}
```

### 4.2 单位状态枚举

```text
enum UnitState {
    IDLE,          // 空闲，没有目标
    SEARCHING,     // 正在索敌
    MOVING,        // 有目标，但不在攻击范围内，正在靠近
    ATTACKING,     // 有目标，且目标在攻击范围内，正在攻击
    RETARGETING,   // 当前目标失效，准备重新索敌
    DEAD,          // 自身死亡
    DISABLED       // 被控制，暂时不能行动
}
```

如果当前 demo 还没有完整状态机，可以先实现最小版：

```text
IDLE
MOVING
ATTACKING
DEAD
```

但索敌逻辑内部仍建议按上述完整流程设计。

## 5. 距离计算规则

根据当前 demo 类型选择距离计算方式。

### 5.1 棋盘格战斗

如果单位在格子上移动，推荐使用曼哈顿距离：

```text
distance = abs(a.grid_x - b.grid_x) + abs(a.grid_y - b.grid_y)
```

如果允许斜向移动，可以使用切比雪夫距离：

```text
distance = max(abs(a.grid_x - b.grid_x), abs(a.grid_y - b.grid_y))
```

### 5.2 2D 自由移动

如果单位使用 Godot 2D 坐标移动，使用：

```text
distance = self.global_position.distance_to(target.global_position)
```

### 5.3 有寻路系统时

如果项目中已经有 AStarGrid2D 或其他寻路系统，推荐优先使用路径距离。

优先级：

```text
寻路距离 > 棋盘距离 > 直线距离
```

当前 demo 可以先使用直线距离或格子距离。

## 6. 目标合法性检查

所有索敌模式都必须先使用统一的目标合法性检查。

### 6.1 合法目标条件

一个目标必须同时满足：

```text
1. target 不为空
2. target 节点仍然有效
3. target 仍然存活
4. target 与自己不是同一阵营
5. target 可以被选中
6. target 没有被移出战场
7. target 没有超出允许索敌范围
8. 如果有寻路系统，目标需要可到达
```

### 6.2 Godot 中需要注意节点有效性

如果使用 GDScript，需要注意已经被 `queue_free()` 的节点。

建议检查：

```gdscript
if target == null:
    return false

if not is_instance_valid(target):
    return false
```

### 6.3 推荐伪代码

```text
function is_valid_target(target):
    if target == null:
        return false

    if target node is invalid:
        return false

    if target.is_alive == false:
        return false

    if target.team == self.team:
        return false

    if target.is_targetable == false:
        return false

    distance = get_distance_to(target)

    if distance > search_range:
        return false

    if path system exists and target is unreachable:
        return false

    return true
```

### 6.4 当前目标合法性检查

每次 AI 更新时，都要先检查当前目标：

```text
if current_target is not valid:
    current_target = null
    state = RETARGETING
```

## 7. 通用索敌流程

两种索敌模式都使用同一个基础流程。

```text
单位 AI 更新
    ↓
检查自身是否死亡
    ↓
检查自身是否被控制
    ↓
检查 current_target 是否仍然合法
    ↓
如果 current_target 失效，清空 current_target
    ↓
如果 current_target 为空，执行索敌
    ↓
根据 target_mode 选择目标
    ↓
如果找到目标：
        current_target = selected_target
        如果目标在 attack_range 内：
            state = ATTACKING
        否则：
            state = MOVING
    ↓
如果没有找到目标：
        state = IDLE
```

## 8. 目标列表获取与过滤

### 8.1 获取候选目标

候选目标来源可以有两种方式：

#### 方式一：从 BattleManager 获取所有单位

```text
all_units = BattleManager.get_all_units()
```

然后在当前单位内部过滤敌人。

#### 方式二：从 BattleManager 获取敌方单位

```text
enemy_units = BattleManager.get_enemy_units(self.team)
```

推荐方式二，逻辑更清晰。

### 8.2 候选目标过滤流程

```text
candidates = []

for unit in enemy_units:
    if is_valid_target(unit):
        candidates.append(unit)
```

如果 `candidates` 为空：

```text
current_target = null
state = IDLE
```

## 9. 模式一：最近目标模式 NEAREST

### 9.1 模式说明

`NEAREST` 模式选择距离自己最近的合法敌人。

适合：

```text
普通近战单位
普通远程单位
坦克
召唤物
基础小兵
```

### 9.2 索敌规则

排序优先级：

```text
1. 距离最近
2. 如果距离相同，选择当前血量更低的
3. 如果血量也相同，选择 unit_id 更小的
```

如果当前没有 `unit_id`，第三条可以暂时忽略。

### 9.3 详细流程

```text
进入 Searching
    ↓
获取敌方单位列表
    ↓
过滤非法目标
    ↓
如果候选目标为空：
        state = IDLE
        current_target = null
        return
    ↓
计算每个候选目标距离
    ↓
选择距离最短的目标
    ↓
设置 current_target
    ↓
如果目标在 attack_range 内：
        state = ATTACKING
    否则：
        state = MOVING
```

### 9.4 推荐伪代码

```text
function find_nearest_target(candidates):
    best_target = null
    best_distance = INF

    for target in candidates:
        distance = get_distance_to(target)

        if distance < best_distance:
            best_distance = distance
            best_target = target
        else if distance == best_distance:
            if target.hp < best_target.hp:
                best_target = target

    return best_target
```

### 9.5 当前目标仍然合法时是否切换

`NEAREST` 模式不建议频繁重新索敌。

推荐规则：

```text
如果 current_target 仍然合法，则继续攻击当前目标
除非 current_target 死亡、消失、不可选中、离开索敌范围或无法到达
```

也就是说：

```text
NEAREST 模式默认有较强目标黏性
```

### 9.6 当前目标死亡

```text
current_target.is_alive == false
    ↓
current_target = null
state = RETARGETING
    ↓
重新寻找最近目标
```

### 9.7 当前目标消失或节点被删除

```text
current_target == null
或 not is_instance_valid(current_target)
    ↓
current_target = null
state = RETARGETING
    ↓
重新索敌
```

### 9.8 当前目标变为不可选中

例如目标进入无敌消失、隐身、死亡动画不可被攻击阶段。

```text
current_target.is_targetable == false
    ↓
current_target = null
state = RETARGETING
    ↓
重新索敌
```

### 9.9 当前目标离开攻击范围

这种情况不要立刻切换目标。

```text
distance_to_target > attack_range
但 distance_to_target <= search_range
    ↓
state = MOVING
继续靠近目标
```

### 9.10 当前目标离开索敌范围

```text
distance_to_target > search_range
    ↓
current_target = null
state = RETARGETING
    ↓
重新寻找最近目标
```

## 10. 模式二：血量最少目标模式 LOWEST_HP

### 10.1 模式说明

`LOWEST_HP` 模式优先攻击血量最低的敌人。

适合：

```text
刺客
狙击手
收割者
执行者类英雄
带斩杀技能的单位
```

### 10.2 血量判断方式

推荐使用血量百分比，而不是绝对血量。

```text
hp_ratio = hp / max_hp
```

原因：

```text
100 / 1000 的坦克比 200 / 300 的脆皮更残
```

### 10.3 排序优先级

推荐排序规则：

```text
1. hp_ratio 最低
2. 当前 hp 最低
3. 距离最近
4. unit_id 更小，保证结果稳定
```

如果当前没有 `unit_id`，第四条可以暂时忽略。

### 10.4 详细流程

```text
进入 Searching
    ↓
获取敌方单位列表
    ↓
过滤非法目标
    ↓
如果候选目标为空：
        state = IDLE
        current_target = null
        return
    ↓
计算每个候选目标 hp_ratio
    ↓
选择 hp_ratio 最低的目标
    ↓
如果 hp_ratio 相同，选择当前 hp 更低的目标
    ↓
如果当前 hp 也相同，选择距离更近的目标
    ↓
设置 current_target
    ↓
如果目标在 attack_range 内：
        state = ATTACKING
    否则：
        state = MOVING
```

### 10.5 推荐伪代码

```text
function find_lowest_hp_target(candidates):
    best_target = null
    best_hp_ratio = INF
    best_hp = INF
    best_distance = INF

    for target in candidates:
        hp_ratio = target.hp / target.max_hp
        distance = get_distance_to(target)

        if hp_ratio < best_hp_ratio:
            best_target = target
            best_hp_ratio = hp_ratio
            best_hp = target.hp
            best_distance = distance
        else if hp_ratio == best_hp_ratio:
            if target.hp < best_hp:
                best_target = target
                best_hp = target.hp
                best_distance = distance
            else if target.hp == best_hp:
                if distance < best_distance:
                    best_target = target
                    best_distance = distance

    return best_target
```

### 10.6 LOWEST_HP 是否需要周期性重新索敌

`LOWEST_HP` 与 `NEAREST` 不同。

因为战场上其他敌人可能被队友打残，所以该模式需要周期性重新评估目标。

推荐：

```text
retarget_interval = 0.3 到 0.5 秒
```

每隔一段时间重新寻找候选目标。

### 10.7 防止 LOWEST_HP 频繁切换

如果每次发现更残的目标就立即切换，单位可能频繁抖动。

因此需要目标黏性规则。

推荐切换条件：

```text
如果 current_target 仍然合法，不一定立刻切换。
只有新目标明显更优，才切换。
```

“明显更优”可以使用以下规则：

```text
new_target.hp_ratio + 0.1 < current_target.hp_ratio
```

意思是：

```text
新目标血量百分比至少比当前目标低 10%，才切换。
```

例如：

```text
当前目标血量：40%
新目标血量：35%
不切换

当前目标血量：40%
新目标血量：25%
切换
```

也可以额外限制距离：

```text
如果新目标距离太远，不切换。
```

推荐规则：

```text
new_target_distance <= current_target_distance + 3
```

如果是像素坐标，则根据项目尺度调整，例如：

```text
new_target_distance <= current_target_distance + 120
```

当前 demo 可以先只实现血量差阈值，不实现距离限制。

### 10.8 LOWEST_HP 的推荐切换逻辑

```text
如果 current_target 无效：
    立即重新索敌

如果 current_target 有效：
    每隔 retarget_interval 重新评估一次

    找到 new_target

    如果 new_target 为空：
        保持当前目标，或者根据合法性进入 IDLE

    如果 new_target == current_target：
        不切换

    如果 new_target.hp_ratio + switch_threshold < current_target.hp_ratio：
        current_target = new_target
    否则：
        继续攻击 current_target
```

推荐：

```text
switch_threshold = 0.1
```

### 10.9 当前目标死亡

```text
current_target.is_alive == false
    ↓
current_target = null
state = RETARGETING
    ↓
立即重新寻找血量最少目标
```

### 10.10 当前目标消失或节点被删除

```text
current_target == null
或 not is_instance_valid(current_target)
    ↓
current_target = null
state = RETARGETING
    ↓
重新索敌
```

### 10.11 当前目标变为不可选中

```text
current_target.is_targetable == false
    ↓
current_target = null
state = RETARGETING
    ↓
重新寻找血量最少目标
```

### 10.12 当前目标离开攻击范围

```text
distance_to_target > attack_range
但 distance_to_target <= search_range
    ↓
state = MOVING
继续靠近目标
```

### 10.13 当前目标离开索敌范围

```text
distance_to_target > search_range
    ↓
current_target = null
state = RETARGETING
    ↓
重新寻找血量最少目标
```

## 11. 统一状态变化过程

### 11.1 没有目标时

```text
state = IDLE
    ↓
进入 AI 更新
    ↓
state = SEARCHING
    ↓
尝试寻找目标
    ↓
找到目标：
        current_target = target
        根据距离进入 MOVING 或 ATTACKING
    ↓
没找到目标：
        state = IDLE
```

### 11.2 目标在攻击范围外

```text
current_target 有效
distance_to_target > attack_range
distance_to_target <= search_range
    ↓
state = MOVING
    ↓
移动系统向 current_target 靠近
```

### 11.3 目标进入攻击范围

```text
current_target 有效
distance_to_target <= attack_range
    ↓
state = ATTACKING
    ↓
攻击系统根据 attack_cooldown 执行攻击
```

### 11.4 当前目标失效

```text
current_target 失效
    ↓
current_target = null
state = RETARGETING
    ↓
进入 SEARCHING
    ↓
重新选择目标
```

### 11.5 自身死亡

```text
self.is_alive == false
    ↓
state = DEAD
current_target = null
停止移动
停止攻击
停止索敌
```

### 11.6 自身被控制

```text
self.is_disabled == true
    ↓
state = DISABLED
保留 current_target
暂停移动
暂停攻击
暂停主动索敌
```

控制结束后：

```text
重新检查 current_target
如果仍然合法：
    根据距离进入 MOVING 或 ATTACKING
否则：
    清空目标并重新索敌
```

## 12. AI 更新频率建议

不要每一帧都全场扫描敌人。

推荐：

```text
基础 AI 更新：每 0.1 秒一次
重新索敌检查：每 0.3 到 0.5 秒一次
```

### 12.1 NEAREST 模式

```text
current_target 有效时，不主动重新索敌
current_target 无效时，立即重新索敌
```

### 12.2 LOWEST_HP 模式

```text
current_target 无效时，立即重新索敌
current_target 有效时，每隔 retarget_interval 重新评估一次
```

## 13. 防抖与目标黏性

### 13.1 为什么需要目标黏性

如果没有目标黏性，单位可能出现：

```text
刚选 A
下一帧 B 更近
切 B
下一帧 A 又更近
切 A
```

表现为：

```text
单位来回转向
单位攻击频率异常
单位移动路径频繁变化
战斗观感很差
```

### 13.2 NEAREST 目标黏性

```text
只要 current_target 合法，就不主动切换
```

除非：

```text
current_target 死亡
current_target 消失
current_target 不可选中
current_target 离开 search_range
current_target 无法到达
```

### 13.3 LOWEST_HP 目标黏性

```text
定期重新评估
但只有新目标明显更残才切换
```

推荐阈值：

```text
lowest_hp_switch_threshold = 0.1
```

切换条件：

```text
new_target.hp_ratio + lowest_hp_switch_threshold < current_target.hp_ratio
```

## 14. 与移动系统的协作

索敌系统只设置 `current_target`。

移动系统负责：

```text
如果 state == MOVING:
    向 current_target 靠近
```

移动前需要再次检查：

```text
current_target 是否仍然有效
```

如果移动过程中目标失效：

```text
停止移动
current_target = null
state = RETARGETING
```

如果使用格子移动：

```text
向目标附近的可攻击格移动
```

而不是移动到目标所在格。

---

## 15. 与攻击系统的协作

攻击系统负责：

```text
1. 判断 current_target 是否有效
2. 判断是否在 attack_range 内
3. 判断 attack_cooldown 是否结束
4. 执行攻击
5. 造成伤害
```

攻击前必须检查目标合法性。

推荐流程：

```text
if current_target is invalid:
    current_target = null
    state = RETARGETING
    return

if distance_to_target > attack_range:
    state = MOVING
    return

if attack_cooldown <= 0:
    attack current_target
    reset attack_cooldown
```

## 16. BattleManager 建议接口

如果当前项目中有 BattleManager，建议增加以下接口。

```text
get_all_units() -> Array
get_enemy_units(team) -> Array
is_battle_running() -> bool
```

推荐单位通过 BattleManager 获取敌方单位，而不是自己遍历整个场景树。

示例：

```text
enemy_units = BattleManager.get_enemy_units(self.team)
```

如果当前项目没有 BattleManager，可以先在战斗场景中维护一个数组：

```text
units = []
```

单位创建时注册：

```text
BattleManager.register_unit(unit)
```

单位死亡或移除时注销：

```text
BattleManager.unregister_unit(unit)
```

## 17. 当前目标死亡事件处理

可以使用两种方式。

### 17.1 轮询方式

每次 AI 更新时检查：

```text
if not is_valid_target(current_target):
    current_target = null
```

优点：

```text
简单稳定
不依赖信号
适合 demo
```

### 17.2 信号方式

目标死亡时发出信号：

```text
target_died(target)
```

攻击者收到后：

```text
if current_target == target:
    current_target = null
    state = RETARGETING
```

优点：

```text
响应更及时
```

当前 demo 推荐先使用轮询方式，后续再补信号。

## 19. 验收标准

实现完成后，需要满足以下效果。

### 19.1 NEAREST 验收标准

```text
单位会自动选择最近的合法敌人
目标活着且合法时不会频繁切换
目标死亡后会重新选择最近敌人
目标离开攻击范围但仍在索敌范围内时，单位会追击
目标离开索敌范围后，单位会放弃并重新索敌
没有敌人时单位进入 IDLE
```

### 19.2 LOWEST_HP 验收标准

```text
单位会优先选择血量百分比最低的合法敌人
血量百分比相同时，选择当前血量更低的敌人
血量也相同时，选择距离更近的敌人
目标死亡后会重新选择血量最低的敌人
目标离开攻击范围但仍在索敌范围内时，单位会追击
目标离开索敌范围后，单位会放弃并重新索敌
当前目标仍合法时，不会因为极小血量差频繁切换
当新目标明显更残时，可以切换目标
```

### 19.3 稳定性验收标准

```text
不会因为 target 被 queue_free 而报错
不会出现 current_target 指向死亡单位后继续攻击
不会出现没有目标时仍然攻击
不会出现单位在两个目标之间高频切换
不会每帧扫描全场导致性能浪费
```
