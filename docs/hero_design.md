# 英雄系统设计文档

> 维护提示：本文档仍是英雄系统的设计入口。当前英雄的实际 UnitData 资源位于 `data/heroes/iron_oath_commander_unit.tres`、`data/heroes/arcane_mentor_unit.tres`、`data/heroes/bloodshadow_hunter_unit.tres`、`data/heroes/boneweaver_unit.tres`；当前数值以 `docs/content_reference.md` 的英雄章节为准。

## 1. 文档目标

本文档用于设计自动对战 Roguelike 自走棋原型中的英雄系统。

英雄不是普通商店单位，而是玩家开局选择的核心单位。英雄决定本局构筑方向，并通过多轮战斗逐步成长，获得专属强化。

第一版英雄系统目标：

1. 游戏开局时玩家选择 1 名英雄。
2. 英雄作为特殊单位加入玩家阵容。
3. 英雄可以上场参与战斗。
4. 英雄不占用普通单位最大上场数量。
5. 英雄不能购买、出售、升星、下阵。
6. 英雄拥有比普通单位更强、更复杂的被动与主动技能。
7. 英雄拥有独立升级机制。
8. 英雄升级后获得专属强化。
9. 英雄引导玩家围绕特定流派进行构筑。

---

## 2. 英雄系统定位

英雄系统用于增强游戏的长期构筑目标。

普通单位主要通过：

- 商店购买
- 备战席调整
- 升星合成
- 遗物联动
- 技能搭配

形成阵容强度。

英雄则用于提供更明确的构筑方向，例如：

| 英雄 | 构筑方向 | 推荐阵容 |
|---|---|---|
| 铁誓统帅 | 防御、护盾、前排、持久战 | 战士、坦克、巨剑骑士、神官、牧师 |
| 奥术导师 | 技能、魔力、法术爆发 | 法师、炼金术士、爆弹投手、游吟诗人、风语者 |
| 血影猎主 | 暴击、刺杀、收割 | 刺客、弓手、巨剑骑士、爆弹投手 |
| 织骨者 | 召唤、亡灵、数量压制 | 亡灵法师、傀儡术士、缚魂祭司、骨巨人、骨龙 |

## 3. 英雄基础规则

### 3.1 选择规则

1. 每局开始前，玩家从英雄列表中选择 1 名英雄。
2. 选择英雄后进入正常游戏流程。
3. Restart 后清空英雄选择，重新进入英雄选择流程。
4. 第一版只允许选择 1 名英雄。
5. 不支持多英雄同时上场。

---

### 3.2 上场规则

1. 英雄作为特殊单位加入玩家阵营。
2. 英雄在战斗中拥有实体单位，可以移动、攻击、释放技能、死亡。
3. 英雄不占用普通单位 `max_active_units`。
4. 如果普通单位最大上场数是 5，则实际战场最多为：

```text
1 名英雄 + 5 名普通单位
```

5. 英雄占用棋盘格。
6. 英雄拥有推荐站位。
7. 英雄不能进入备战席。
8. 英雄不能下阵。
9. 英雄不能出售。
10. 英雄不能升星。
11. 英雄死亡只影响当前战斗，下一场战斗会重新生成。

---

### 3.3 成长规则

当前实现使用经验条升级，而不是固定波次直接升级。

```text
50 经验升级一次
普通关胜利：+10 经验
精英关胜利：+20 经验
Boss 关胜利：+30 经验
```

英雄每次升级时，玩家获得一次强化三选一。专属强化不足 3 个时，使用随机基础属性强化补齐选项。

英雄等级会通过成长曲线提高基础属性；Restart 后清空英雄选择、等级、经验和本局强化。

---

### 3.4 英雄强化规则

英雄升级后，从该英雄专属强化池中随机抽取 3 个强化选项供玩家选择。

强化类型包括：

1. 强化英雄自身属性。
2. 强化英雄被动技能。
3. 强化英雄主动技能。
4. 解锁新的被动效果。
5. 为特定类型单位提供全局增益。
6. 改变某个技能机制。
7. 强化特定阵容方向。

英雄强化只在本局内生效。

Restart 后清空英雄等级和强化。

## 4. 建议数据结构

### 4.1 HeroData

建议新增英雄数据结构：

```text
hero_id
hero_name
hero_unit_data
description
base_passive_ids
base_active_skill_id
upgrade_pool
recommended_cells
```

字段说明：

| 字段 | 说明 |
|---|---|
| `hero_id` | 英雄唯一 ID |
| `hero_name` | UI 显示名称 |
| `hero_unit_data` | 英雄对应的 UnitData 或类似资源 |
| `description` | 英雄说明 |
| `base_passive_ids` | 英雄基础被动列表 |
| `base_active_skill_id` | 英雄基础主动技能 |
| `upgrade_pool` | 英雄专属升级池 |
| `recommended_cells` | 英雄推荐站位 |

---

### 4.2 HeroUpgradeData

建议新增英雄升级数据结构：

```text
upgrade_id
upgrade_name
description
hero_id
effect_type
value
required_level
```

字段说明：

| 字段 | 说明 |
|---|---|
| `upgrade_id` | 强化唯一 ID |
| `upgrade_name` | 强化名称 |
| `description` | UI 描述 |
| `hero_id` | 绑定的英雄 ID |
| `effect_type` | 强化类型 |
| `value` | 主要数值 |
| `required_level` | 所需英雄等级 |

---

### 4.3 HeroManager

建议新增 `HeroManager` 管理英雄状态。

职责：

```text
selected_hero
hero_level
hero_upgrades
select_hero()
spawn_hero()
gain_hero_level()
generate_hero_upgrade_options()
apply_hero_upgrade()
reset_hero()
```

`HeroManager` 不应处理普通单位商店、备战席、出售、升星逻辑。

## 5. 英雄一：铁誓统帅 / Iron Oath Commander

### 5.1 定位

核心承伤与团队防御英雄。

适合围绕以下单位构筑：

- 战士
- 坦克
- 巨剑骑士
- 神官
- 牧师
- 守卫队长
- 其他承伤或治疗单位

核心关键词：

```text
防御
护盾
前排
持久战
低血保护
```

---

### 5.2 基础属性

```text
hero_id = iron_oath_commander
unit_name = Iron Oath Commander
unit_type = hero_iron_oath_commander
role = hero_tank

max_hp = 320
attack_damage = 18
defense = 35
crit_chance = 0.0
crit_damage_multiplier = 1.5

attack_interval = 1.2
attack_range = 60.0
search_range = 999.0
move_speed = 70.0

max_mana = 120
mana_regen_per_second = 10.0
target_mode = NEAREST
```

---

### 5.3 被动技能 1：铁誓军势 / Iron Oath Legion

效果：

```text
战斗开始时，所有玩家前排单位获得 15 + 0.1*defense 防御。
如果该单位是 warrior、tank、greatsword_knight 或其他承伤单位，额外获得 20 + defense + 0.1*max_hp  护盾。
```

强化方向：

```text
英雄等级 2 后可强化：
前排单位额外获得 10% 最大生命值的护盾。
前排单位额外获得 10% 防御的防御。
```

设计目的：

让铁誓统帅天然适合前排防守阵容。

---

### 5.4 被动技能 2：不倒战线 / Unbroken Line

效果：

```text
当任意玩家前排单位生命值首次低于 40% 时，为其添加等同于已损失生命值的护盾。
每个单位每场战斗只触发一次。
```

强化方向：

```text
英雄等级 3 后可强化：
触发时额外恢复该单位 30% 魔力。
```

设计目的：

提升前排单位的续航和容错。

---

### 5.5 主动技能：统帅号令 / Commanding Order

释放规则：

```text
魔力满后自动释放。
```

普通效果：

```text
所有玩家单位获得 25 + defense + 0.1*max_hp 护盾。
前排单位额外获得 +20 + 0.1*defense 防御，持续 5 秒。
```

等级 4 强化：

```text
所有玩家单位获得 40 + 1.5*defense + 0.2*max_hp 护盾。
前排单位额外获得 +35 + 0.2*defense 防御，持续 6 秒。
```

设计目的：

作为团队防御爆发技能，帮助队伍扛过敌方爆发阶段。

---

### 5.6 专属升级选项

| 升级名 | 效果 |
|---|---|
| 坚不可摧 | 英雄自身防御 +50 |
| 铁壁扩散 | 统帅号令的防御加成也影响中排单位 |
| 护卫协同 | 每有 1 个承伤单位，全队防御 +10 |
| 战线回响 | 玩家单位获得护盾时，恢复 10 魔力，每单位每 2 秒最多触发一次 |
| 最终防线 | 英雄死亡时，所有玩家单位获得 100 + defense 护盾 |
| 重甲阵列 | 所有前排单位获得最大生命值0.2*max_hp |
| 护盾训练 | 玩家单位获得的护盾值提高 15% |
| 坚守号角 | 统帅号令额外治疗前排单位 10% 已损生命 |

---

### 5.7 推荐站位

玩家侧推荐：

```text
(6,3), (6,2), (6,4), (5,3), (5,2), (5,4)
```

定位说明：

```text
前排中心，作为主坦或副主坦存在。
```

## 6. 英雄二：奥术导师 / Arcane Mentor

### 6.1 定位

技能流、魔力流、法术爆发英雄。

适合围绕以下单位构筑：

- 法师
- 炼金术士
- 爆弹投手
- 游吟诗人
- 风语者
- 牧师
- 神官
- 其他依赖主动技能的单位

核心关键词：

```text
技能伤害
魔力回复
范围伤害
法术爆发
技能联动
```

---

### 6.2 基础属性

```text

unit_name = Arcane Mentor
unit_type = hero_arcane_mentor
role = hero_damage

max_hp = 180
attack_damage = 26
defense = 5
crit_chance = 0.05
crit_damage_multiplier = 1.5

attack_interval = 1.35
attack_range = 140.0
search_range = 999.0
move_speed = 85.0

max_mana = 100
mana_regen_per_second = 14.0
target_mode = NEAREST
```

---

### 6.3 被动技能 1：奥术回流 / Arcane Reflow

效果：

```text
每当玩家单位释放主动技能时，奥术导师恢复 8 魔力。
如果释放技能的单位是 mage、alchemist、bomb_thrower 或其他技能输出单位，额外恢复 4 魔力。
```

强化方向：

```text
英雄等级 2 后可强化：
触发时，随机 1 个玩家单位恢复 5 魔力。
```

设计目的：

让技能流阵容形成连锁释放节奏。

---

### 6.4 被动技能 2：法术共鸣 / Spell Resonance

效果：

```text
玩家单位造成主动技能伤害时，伤害提高 10%。
```

强化方向：

```text
英雄等级 3 后可强化：
主动技能伤害提高 18%。
```

设计目的：

强化技能输出单位，让技能阵容形成明确成长方向。

---

### 6.5 主动技能：奥术风暴 / Arcane Storm

释放规则：

```text
魔力满后自动释放。
```

普通效果：

```text
以当前目标为中心，对范围 120 内所有敌人造成 attack_damage * 2.2 的技能伤害。
```

等级 4 强化：

```text
范围提升到 150。
伤害提升到 attack_damage * 2.8。
如果命中 3 个以上敌人，所有玩家单位恢复 15 魔力。
```

设计目的：

作为范围技能输出核心，适合法术和 AoE 阵容。

---

### 6.6 专属升级选项

| 升级名 | 效果 |
|---|---|
| 魔力涌动 | 所有玩家单位魔力回复速度 +10% |
| 法术穿透 | 玩家主动技能伤害无视目标 20% 防御 |
| 连锁施法 | 奥术导师释放主动技能后，随机友方单位恢复 30 魔力 |
| 炼金共振 | 场地持续伤害类技能伤害 +20% |
| 爆裂奥术 | 奥术风暴每额外命中 1 个敌人，伤害提高 5%，最多提高 25% |
| 元素过载 | 法师、炼金术士、爆弹投手攻击力 +12% |
| 魔力护盾 | 玩家单位释放主动技能后获得 10 护盾 |
| 快速吟唱 | 奥术导师最大魔力 -15，但技能伤害降低 8% |

## 7. 英雄三：血影猎主 / Bloodshadow Hunter

### 7.1 定位

暴击、刺杀、收割英雄。

适合围绕以下单位构筑：

- 刺客
- 弓手
- 巨剑骑士
- 爆弹投手
- 炼金术士
- 其他高暴击 / 高爆发单位

核心关键词：

```text
暴击
收割
低血量目标
击杀收益
标记目标
```

---

### 7.2 基础属性

```text
hero_id = bloodshadow_hunter
unit_name = Bloodshadow Hunter
unit_type = hero_bloodshadow_hunter
role = hero_damage

max_hp = 220
attack_damage = 30
defense = 8
crit_chance = 0.15
crit_damage_multiplier = 1.8

attack_interval = 0.9
attack_range = 70.0
search_range = 999.0
move_speed = 150.0

max_mana = 90
mana_regen_per_second = 12.0
target_mode = LOWEST_HP
```

---

### 7.3 被动技能 1：猎杀标记 / Hunt Mark

效果：

```text
战斗开始时，随机标记 1 个敌方后排单位。
玩家单位攻击被标记目标时，伤害提高 15%。
```

强化方向：

```text
英雄等级 2 后可强化：
标记目标死亡后，重新标记 1 个新的敌人。
```

设计目的：

制造“集火目标”和“后排威胁”玩法。

---

### 7.4 被动技能 2：血影收割 / Bloodshadow Harvest

效果：

```text
玩家单位击杀敌人时，击杀者恢复 20 生命和 15 魔力。
如果击杀者是 assassin 或 archer，额外获得 +10% 暴击率，持续 5 秒。
```

强化方向：

```text
英雄等级 3 后可强化：
击杀回血提高到 35。
恢复魔力提高到 25。
```

设计目的：

强化击杀滚雪球和收割体系。

---

### 7.5 主动技能：血影突袭 / Bloodshadow Assault

释放规则：

```text
魔力满后自动释放。
```

普通效果：

```text
对当前生命比例最低的敌人造成 attack_damage * 2.6 的技能伤害。
如果目标生命比例低于 50%，伤害提高 30%。
如果该技能击杀目标，立即恢复 50 魔力。
```

等级 4 强化：

```text
伤害提升到 attack_damage * 3.2。
如果该技能击杀目标，额外对最近敌人释放一次 60% 威力的血影突袭。
```

设计目的：

提供强力斩杀能力，引导玩家构筑暴击和收割阵容。

---

## 8. 英雄升级节点设计

第一版推荐英雄等级最高为 4。

| 英雄等级 | 达成条件 | 解锁内容 |
|---|---|---|
| 1 | 开局选择英雄 | 基础被动和主动技能 |
| 2 | 第 3 波胜利后 | 选择 1 个英雄专属强化 |
| 3 | 第 6 波胜利后 | 选择 1 个英雄专属强化 |
| 4 | 第 9 波胜利后 | 选择 1 个终极强化或主动技能强化 |

可选方案：

```text
每次英雄升级时，从专属升级池中随机抽取 3 个未获得强化。
玩家选择 1 个。
已选择过的强化不再出现。
```

---

## 9. 英雄升级强化类型

英雄强化可以分为以下几类：

### 9.1 属性强化

示例：

```text
英雄自身 max_hp +15%
英雄自身 attack_damage +20%
英雄自身 defense +20
英雄自身 mana_regen_per_second +20%
```

---

### 9.2 被动强化

示例：

```text
铁誓军势的防御加成提高。
法术共鸣的技能伤害加成提高。
猎杀标记目标死亡后重新标记。
```

---

### 9.3 主动技能强化

示例：

```text
统帅号令护盾提高。
奥术风暴范围变大。
血影突袭击杀后追加释放。
```

---

### 9.4 阵容联动强化

示例：

```text
每有 1 个承伤单位，全队防御 +3。
每有 1 个技能输出单位，全队魔力回复 +3%。
每有 1 个刺客或弓手，全队暴击伤害 +5%。
```

---

### 9.5 机制改变强化

示例：

```text
护盾触发时恢复魔力。
技能命中多个目标时返还魔力。
击杀后追加攻击或技能。
```

## 10. 第一版实现边界

第一版只实现：

1. 开局选择 1 个英雄。
2. 英雄加入战场。
3. 英雄不占普通单位上场数量。
4. 英雄有固定被动和主动技能。
5. 英雄按波次升级。
6. 英雄升级时弹出专属强化三选一。
7. 英雄强化只影响本局。
8. Restart 后重新选择英雄。

第一版暂不实现：

1. 英雄装备。
2. 英雄升星。
3. 英雄商店。
4. 英雄出售。
5. 英雄死亡后永久失效。
6. 英雄天赋树 UI。
7. 多英雄同时上场。
8. 英雄羁绊。
9. 英雄皮肤。
10. 英雄剧情。
11. 英雄持久化存档。

## 11. 实现建议

建议新增以下内容：

```text
scripts/hero_manager.gd
scripts/hero_data.gd
scripts/hero_upgrade_data.gd
data/heroes/iron_oath_commander_unit.tres
data/heroes/arcane_mentor_unit.tres
data/heroes/bloodshadow_hunter_unit.tres
```

英雄定义本体由 `HeroManager` 加载和维护，英雄上场用的运行时单位数据使用 `data/heroes/*_unit.tres`。

建议不要把英雄逻辑塞进：

```text
main.gd
unit.gd
roster_manager.gd
reward_manager.gd
```

其中：

- `HeroManager` 负责英雄选择、等级、强化、生成数据。
- `BattleManager` 只负责按照 `HeroManager` 提供的数据生成英雄单位。
- 英雄主动技能和英雄被动触发通过现有 `UnitSkill` 入口转发到 `scripts/combat/active_skill_caster.gd` 与 `scripts/combat/passive_resolver.gd`。
- `RewardPanel` 或类似 UI 可以复用来显示英雄升级三选一。

## 12. 验收标准

英雄系统实现后，应能验证：

1. 开局能选择 1 名英雄。
2. 选择英雄后进入正常准备阶段。
3. 英雄会生成在棋盘上。
4. 英雄不占用普通单位最大上场数量。
5. 英雄不能进入商店、备战席、出售、升星系统。
6. 英雄死亡后本场不再行动。
7. 下一场战斗英雄会重新生成。
8. 英雄能正常攻击和释放主动技能。
9. 英雄被动能正常触发。
10. 英雄在指定波次后升级。
11. 英雄升级时能出现专属强化三选一。
12. 选择强化后效果立即或下一场生效。
13. 已选择过的英雄强化不会重复出现。
14. Restart 后英雄选择、等级和强化清空。
15. 普通单位、商店、备战席、遗物、奖励、随机敌人和战斗统计不受破坏。
